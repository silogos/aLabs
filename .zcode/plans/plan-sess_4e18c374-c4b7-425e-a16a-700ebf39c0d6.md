# Auth domain → Postgres (Drizzle), fase pertama dari migrasi data layer

Scope: **users, sessions, accounts, password resets pindah ke Postgres**. Semua koleksi lain (orgs, projects, tasks, dll.) tetap in-memory — modul lain bermigrasi bertahap di fase berikutnya. Postgres jadi **wajib** (fail fast tanpa `DATABASE_URL`); data demo (6 user Northwind) **auto-seed** saat tabel users kosong.

## 1. Dependensi & skema
- Install: `drizzle-kit` (root devDep), `postgres` / postgres-js driver (dep `@pmin/api`). `drizzle-orm@0.39.3` sudah ada di `@pmin/core`.
- `packages/core/src/db/schema.ts` — tambah tabel (plural, sesuai data-model doc; `users` sudah ada):
  - `sessions`: id uuid PK, token varchar unique, user_id → users.id, expires_at, created_at
  - `accounts`: id uuid PK, user_id → users.id, provider varchar(31), provider_account_id nullable, password_hash nullable, created_at (Better Auth-shaped)
  - `password_resets`: id uuid PK, token varchar unique, user_id, expires_at, used_at nullable, created_at
- Initial migration di-generate ke `./drizzle` via drizzle-kit.

## 2. Klien DB + boot sequence (`packages/api/src/db/pg.ts`)
- Singleton `drizzle(postgres(DATABASE_URL))`; tanpa `DATABASE_URL` → error jelas saat boot.
- `ready` promise: cek koneksi → jalankan migrasi (drizzle migrator; dir dari `MIGRATIONS_DIR` atau cari `drizzle/` ke atas dari cwd) → seedAuth jika users kosong → seed in-memory sisanya dengan id user dari DB.
- `app.ts`: `seed()` di import-time diganti `export const ready`; middleware pertama `await ready` sebelum resolveUser.

## 3. Repository auth (`packages/api/src/db/auth-repo.ts`)
- Mapper baris DB ↔ domain (snake_case + Date → camelCase + ISO string).
- Fungsi: getUserByEmail/ById, listUsers, getUsersByIds, insertUser, updateUserProfile; insertSession, findValidSession, deleteSession, revokeUserSessions; findAccount, insertAccount, updateAccountPassword; insertPasswordReset, findValidPasswordReset, markUsed.
- `store.ts`: hapus koleksi users/sessions/accounts/passwordResets (+ type-nya); sisanya tetap.

## 4. Rewiring route (blast radius dari eksplorasi)
- `lib/auth.ts`: `resolveUser` jadi async (kedua call site sudah async).
- `modules/auth/routes.ts`: semua operasi store → repo; `issueSession` async; `createUserWithWorkspace` insert user ke DB lalu buat personal org + member in-memory dengan user fresh ter-embed; sesi demo `"demo-…"` dihapus (auto-login sudah tidak ada).
- `modules/user/routes.ts` PATCH `/me`: `UPDATE users RETURNING`, respons user baru.
- `modules/organization/routes.ts`: invitation accept pakai repo (async sudah); GET members menghidrasi `member.user` fresh dari DB (menghindari data basi setelah PATCH /me).
- `modules/reporting/routes.ts`: dashboard handler jadi async, workload dari `listUsers()`.
- Documents (`editedBy`/`uploadedBy`): tetap bake `c.get("user")` — sudah fresh per request, tanpa perubahan.

## 5. Split seed
- `seedAuth(db)`: bila tabel users kosong → insert 6 user + credential account (scrypt `password123`); kembalikan user berdasarkan email.
- Seed in-memory menerima daftar user itu untuk memberships, assignee task, activity, dan embed; tanpa membuat user/sesi lagi.

## 6. Env, scripts, docker
- `apps/web/.env` (gitignored): `DATABASE_URL=postgres://alabs:alabs@localhost:5432/alabs` (Next memuat env dari app dir); `.env.example` diupdate.
- Script root: `db:generate`, `db:migrate` (fallback manual; boot tetap auto-migrate).
- Dockerfile: COPY `drizzle/` → `/app/drizzle` + `MIGRATIONS_DIR`; docker-compose web: set `DATABASE_URL`.
- README (quick start: `pnpm dev:db` + `pnpm dev`), arsitektur doc: catatan status migrasi (auth di PG, sisanya in-memory).

## 7. Verifikasi
- `pnpm dev:db` → generate migration → boot dev (auto-migrate + auto-seed); `psql` cek 6 baris users + accounts.
- curl: login aisha/password123, register user baru (muncul di psql), logout, forgot→reset→login password baru, `/auth/me`.
- Cross-module: GET /organizations/:id/members (user ter-hidrasi), dashboard workload.
- `pnpm typecheck`; browser login smoke; `docker compose up --build` + login smoke di container.

## Catatan risiko
- HMR dev bisa re-run init: migrasi idempoten, seed di-guard kekosongan — aman.
- Embed user di documents dibuat saat write — tetap segar; embed member dihidrasi ulang saat read; ini keterbatasan sementara yang bisa diterima hingga modul lain ikut pindah.
- Driver postgres-js murni JS — aman untuk Turbopack/bundling standalone.
