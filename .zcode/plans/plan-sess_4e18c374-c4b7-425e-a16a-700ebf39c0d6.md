# Refactor pmin to full-stack Next.js

Single Next.js App Router app (`apps/web`, port 3000) that serves both the UI and the existing Hono API in-process. Auth = current hand-rolled APIs + ported login UI. Deployment = one Docker service.

## Phase 0 — Branch prep
- Merge `feat/auth-api` → `main` (it's 1 clean commit ahead and this work builds on it), then cut `feat/next-migration` from `main`.

## Phase 1 — API becomes an importable package
- `git mv apps/api packages/api`, rename to `@pmin/api`, consumed as raw TS source (same pattern as `@pmin/core` — drop the `tsc` build, keep typecheck).
- Split startup: `app.ts` exports the Hono `app` (seed on import is fine); new tiny `serve.ts` optional standalone entry (tsx) for API-only debugging.
- Replace `serveStatic` uploads route with a small `node:fs` handler (serveStatic doesn't work inside Next route handlers). CORS middleware removed (same-origin now).
- Codemod: strip `.js` extensions from relative imports in `packages/api/src` and `apps/web/src` (Next's bundler doesn't do the `.js → .tsx` mapping Vite did).
- Fix `turbo.json`, root scripts (`dev:api` removed / `dev:web` becomes the only dev), `.env.example` (drop `VITE_API_URL`; `WEB_URL=http://localhost:3000`).

## Phase 2 — Scaffold Next.js app
- Replace Vite in `apps/web` with `create-next-app` (TypeScript, App Router, src dir, **no Tailwind** — keep the existing 1,072-line hand-written CSS).
- `next.config.ts`: `transpilePackages: ["@pmin/core", "@pmin/editor", "@pmin/api"]`, `output: "standalone"` (Docker).
- Root `layout.tsx`: metadata from `index.html` (title, viewport), favicon SVG → `app/icon.svg`, import `styles.css` + `@pmin/editor/editor.css` as globals.
- Delete Vite artifacts (`vite.config.ts`, `index.html`, `dist/`); `api.ts` keeps `BASE = "/api"` — same origin now, no proxy needed.

## Phase 3 — Mount the API
- `src/app/api/[[...route]]/route.ts`: delegate every method to `app.fetch(req)` using `basePath("/api")` composition (`export const runtime = "nodejs"`, `dynamic = "force-dynamic"`).
- `src/app/uploads/[...path]/route.ts`: delegate to the unprefixed app (keeps `FileRef.url = "/uploads/…"` working unchanged).
- Verify with curl: seed loads, endpoints respond, uploads serve.

## Phase 4 — App shell + view routes (behavior parity)
- Route group `(app)` with a client layout: `QueryClientProvider` + `AppProvider` + Sidebar/Topbar/overlays shell (overlays — drawer, modals, ⌘K, toasts — stay in context state, exactly as today).
- 7 pages: `/dashboard`, `/tasks`, `/documents`, `/planning`, `/meetings`, `/reports`, `/agreements` — all `"use client"` (the app is 100% client-fetched react-query; the tasks-store singleton makes views client-only anyway). No RSC conversion in this refactor.
- `view` state → `usePathname`/`router.push`; `setView` callers (Sidebar, CommandPalette, MobileNav) become navigations; `switchProject` lands on `/dashboard`; drop `alabs-view` localStorage key (URL is the source of truth now).

## Phase 5 — Auth UI + close the loop
- Port `designs/auth/` screens to routes: `/login`, `/register`, `/forgot-password`, `/reset-password` (+ Google SSO button → `GET /api/auth/oauth/google`). Skip `mfa-verify` (no backend) and `sso-handshake` (server-side redirect makes it unnecessary).
- Extend `api.ts`: `login`, `register`, `logout`, `forgotPassword`, `resetPassword`.
- `middleware.ts`: no `alabs_session` cookie → redirect to `/login` (cookie presence only; real validation via `/auth/me`).
- Remove the demo auto-login fallback in `resolveUser` (no more silent seed-user auth).
- Logout in the account menu → `api.logout` → `/login` + `queryClient.clear()`.
- API tweaks: OAuth failure redirect → `/login?authError=…`; `WEB_URL` default → port 3000.

## Phase 6 — Docker + docs
- New `apps/web` Dockerfile (multi-stage, Next standalone output, uploads volume).
- `docker-compose.yml`: single `web` service on 3000 (drop the `api` service).
- Docs: new **ADR 0008** (Next.js App Router as single web+API deployment, Hono kept as in-process module), update `01-architecture.md` stack table + `README.md` (commands, ports, demo credentials `password123`).

## Known risks (handled during implementation)
- Turbopack + workspace raw-TS source: `transpilePackages` should cover; if not, fall back per-issue.
- Editor CSS import from a workspace package in the root layout: if Next balks, import it inside a client wrapper or inline the 38-line file.
- Dev hot-reload re-seeds the in-memory store — acceptable for prototype (production standalone is a single long-lived process).
