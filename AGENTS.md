# Repo rules — pmin

aLabs — a documentation-first project management platform. pnpm + Turborepo monorepo: User → Organization → Project → business modules (tasks, documents, planning, meetings, agreements, reporting, client portal, notifications, billing, AI).

## Layout

| Path | What it is |
|------|------------|
| `apps/web` | Next.js 16 + React 19 frontend (`@pmin/web`), TanStack Query, Tailwind-less custom CSS, vitest |
| `packages/api` | Hono backend (`@pmin/api`), zod validation, vitest |
| `packages/core` | Shared core + DB (`@pmin/core`, exports `.` and `./db`), Drizzle ORM + postgres |
| `packages/editor` | Editor package (tiptap; version pinned via pnpm overrides) |
| `drizzle/` | Generated migrations (drizzle-kit, config at repo root) |
| `designs/` | Standalone HTML prototypes — the design source of truth; port UI from here, don't freehand it |
| `docs/` | All product & engineering documentation (see rules below) |

Layering: `web` → `api` → `core`. Sensitive areas (API contract, data model, architecture) have specs under `docs/tech/` — read the matching doc before changing them.

## Commands

```bash
pnpm dev              # all (turbo); or dev:web / dev:api / dev:db (docker postgres)
pnpm typecheck        # turbo run typecheck — run before pushing; scope: pnpm --filter @pmin/web typecheck
pnpm test             # turbo run test (vitest); scope: pnpm --filter @pmin/api test
pnpm lint             # eslint (web)
pnpm db:generate      # drizzle-kit generate — after schema edits in packages/core
pnpm db:migrate       # drizzle-kit migrate
pnpm db:studio        # drizzle studio
```

## Gotchas

- **Next.js 16 is not the Next.js you know.** `apps/web/AGENTS.md` is auto-generated by `next dev` and flags breaking changes — read the guide it points to (`node_modules/next/dist/docs/`) before writing web code. Never edit or delete that file; `next dev` regenerates it.
- **Multi-tenancy is the #1 rule** (see `docs/tech/02-conventions.md`): every query on an org/project-scoped table MUST filter by the active tenant, resolved once in `tenantContext`. A missed scope is a data leak.
- Data conventions: UUID v7 string PKs, `timestamptz` UTC, soft delete via `deleted_at`, audit columns `created_by`/`updated_by` from `ctx.user.id` — never client input.
- Naming: snake_case tables/columns, kebab-case logic files, PascalCase React files, permission keys `<module>:<action>`.

## Documentation

1. **All documentation lives in `docs/`.**
   - Product/foundation/module specs: `docs/`, `docs/foundation/`, `docs/modules/`
   - Technical docs & ADRs: `docs/tech/`
   - Visual identity & design specs: `docs/design/`
   - Per-feature implementation/migration plans: `docs/plans/`
   - The only exception is the root `README.md`. Never create standalone `.md` docs in the repo root or inside source directories; plan/spec files discovered elsewhere must be moved into `docs/`.

2. **Docs are updated in the same change, not later.**
   - Any change that alters documented behavior — API contract, data model, conventions, architecture, module/foundation specs — must update the corresponding document under `docs/` in the same PR.
   - Pure code changes with no documented-behavior impact don't require doc edits, but if in doubt, update the doc.
   - New significant decisions get an ADR in `docs/tech/adr/` (next number in sequence).
